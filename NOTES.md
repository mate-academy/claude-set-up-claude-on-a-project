# NOTES

## CLAUDE.md: що залишив і що прибрав

Залишив тільки те, що Claude не побачить з першого погляду на код або що він може зробити неправильно: три команди з `package.json` плюс те, що CI на Node 22 запускає lint перед тестами; конвенції у форматі «роби X, не Y» (CommonJS замість ES-модулів, `node:test` + supertest замість Jest, дані тільки через `db/store.js`, єдиний формат помилок `{ "error": ... }`, без нових залежностей без потреби); і коротку архітектуру з рецептом «як додати новий ресурс».

Прибрав те, що дала чернетка від `/init`, але Claude і так прочитає з коду: опис кожного ендпоінта, перелік полів користувача, вміст `.eslintrc.json`, інструкції з установки й відкриття терміналу з README. Секретів і разових задач у файлі немає — `.env` тільки згадується як заборонений до читання в `settings.json`, а не в `CLAUDE.md`.

## Permission rules

- **allow:** `npm test`, `npm run lint`, `git status`, `git diff` — безпечні команди, які запускаю постійно; не треба підтверджувати кожен раз.
- **ask:** `git push` і `npm install` — пуш іде в спільний репозиторій, а встановлення пакетів змінює `package-lock.json`, тому хочу бачити кожен такий крок.
- **deny:** читання й редагування `.env` (і `cat .env`), `git push --force` / `-f`, `git reset --hard`, `rm -rf`.

Без deny-правил Claude міг би прочитати `.env` і вивести секрети в чат або логи, переписати чужу історію в `main` force-пушем чи безповоротно знищити незакомічену роботу через `reset --hard` / `rm -rf`. Deny має пріоритет над ask, тому force-push заблокований навіть попри правило ask для `git push`.

Обмеження: Bash-правила працюють за префіксом, тому `git push origin main --force` (прапорець у кінці) або `less .env` формально не покриті. Основний захист `.env` — правило `Read(./.env)`, а прапорці force-push треба писати одразу після `git push`.

## Знахідка: .gitignore не ігнорує секрети

У `.gitignore` рядки `.env` і `.claude/settings.local.json` мають пробіли на початку, а для Git ці пробіли — частина шаблону. Тому `git check-ignore .env .claude/settings.local.json` нічого не повертає: обидва файли зараз можна випадково закомітити. Додаток я не змінював (за умовою це поза межами задачі), але це варто виправити окремим комітом — прибрати пробіли на початку рядків.

## Перевірка

- `.claude/settings.json` — валідний JSON; Claude Code CLI 2.1.x його підхоплює (бачить усі 6 allow-правил і застосовує їх, коли робочій папці довірено).
- `/memory` і `/permissions` — перевіряю в інтерактивній сесії: `claude` у корені проєкту → прийняти trust dialog → `/memory` (очікую `CLAUDE.md` як project memory) → `/permissions` (очікую правила allow / ask / deny) → питання «How do I run the tests here?» (очікую `npm test` з `CLAUDE.md`).
