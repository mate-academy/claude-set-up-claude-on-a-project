## 1. Що я додав у CLAUDE.md, що залишив поза ним і чому

`CLAUDE.md` створено після вивчення реального коду проєкту: `server.js`, `routes/`, `db/store.js`, тестів, конфігурації ESLint і CI. Тому кожне правило в ньому відповідає тому, як проєкт уже влаштований.

**Що додав:**
- один рядок з описом проєкту;
- **Commands**: `npm run dev`, `npm test`, запуск одного тестового файлу, `npm run lint`, а також примітку, що CI запускає lint і тести на Node 22;
- **Architecture**: `server.js` експортує `app` і запускає сервер лише при прямому запуску, тому тести можуть його імпортувати. Один файл роутера на ресурс у `routes/`. Доступ до даних лише через `db/store.js`, сховище в пам'яті скидається після перезапуску;
- **Conventions**: CommonJS, а не ES-модулі; `node:test` + `supertest`, а не Jest; маршрути працюють з даними тільки через функції store; помилки повертаються як `{ "error": "..." }` з кодом 400 або 404; `Number(req.params.id)` перед пошуком; ніколи не читати й не комітити `.env`.

**Що залишив поза ним:**
- те, що й так видно з коду (переказ кожного ендпоінта, список залежностей), щоб файл лишався коротким;
- одноразові нотатки й завдання курсу: вони потрібні лише зараз і в кожній наступній сесії тільки заважали б;
- будь-які секрети й значення з `.env`: `CLAUDE.md` комітиться в репозиторій і завантажується в кожну сесію.

## 2. Які правила дозволів я додав і що могло б піти не так без заборонних правил

У `.claude/settings.json`:

- **allow** `Bash(npm test:*)`: Claude може запускати тести без постійних підтверджень. Це безпечна команда, яку запускають найчастіше;
- **ask** `Bash(git push:*)`: перед кожним надсиланням змін на GitHub Claude питає дозволу;
- **deny** `Read(./.env)`: Claude не читає файл із секретами;
- **deny** `Bash(git push --force:*)` і `Bash(git push -f:*)`: заборонено примусове надсилання змін, і в повній, і в короткій формі.

**Без заборонних правил:**
- Claude міг би прочитати `.env`, і секрети (паролі, ключі, `DATABASE_URL`) потрапили б у контекст розмови, а звідти, можливо, у код, коміти чи логи;
- примусовий push міг би перезаписати історію віддаленої гілки й безповоротно знищити чужі або власні коміти.

Окремо я виправив `.gitignore`: через пробіли на початку рядків Git не ігнорував `.env` і `.claude/settings.local.json`. Тепер ці файли не потраплять у коміт випадково.

## 3. Перевірка налаштувань

**CLAUDE.md.** Після запуску нової сесії Claude Code автоматично завантажив `CLAUDE.md` з кореня проєкту. Це підтвердила команда `/memory`. Отже, правила проєкту діють з першого повідомлення, і їх не треба повторювати вручну.

**Дозволи.** Команда `/permissions` показала, що всі правила з `.claude/settings.json` активні:

| Тип | Правило | Навіщо | Від чого захищає |
|---|---|---|---|
| Allow | `Bash(npm test:*)` | тести запускаються без підтвердження | від зайвих запитів на безпечну дію, яку виконують найчастіше |
| Ask | `Bash(git push:*)` | кожен push треба підтвердити | від надсилання на GitHub змін, які я ще не переглянув |
| Deny | `Read(./.env)` | Claude не може прочитати `.env` | від витоку секретів у контекст, код, коміти чи логи |
| Deny | `Bash(git push --force:*)`, `Bash(git push -f:*)` | примусовий push заблоковано повністю | від перезапису історії віддаленої гілки й втрати комітів |

Правила deny мають пріоритет над ask і allow. Тому `git push --force` заблоковано, хоча звичайний `git push` лише потребує підтвердження. Заборонені обидві форми, `--force` і `-f`, бо правило збігається з початком команди, і без короткої форми заборону можна було б обійти.
