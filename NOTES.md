# CLAUDE.md — Рішення про вміст

## Що я вклав і чому

### ✅ Включив

**Commands** — це критично важливо. Claude потребує знати, як запустити dev сервер, тести та лінтер. Без цього він буде гадати або робити помилкові припущення.

**Conventions** — три основні правила про структуру коду:
- Чому роутери в `routes/`? Щоб Claude знав, де шукати endpoints
- Чому через `db/store.js`? Щоб він ніколи не мутував дані напряму з роутів — це запобігає несправностям
- ESLint винятки для `_` параметрів — щоб він не пропонував видаляти потрібні параметри (як в middleware)

**Architecture** — деталь про те, як все з'єднується. Це дорожна карта для Claude — він знає, що `server.js` — точка входу, що кожен ресурс має свій файл, як дані текуть.

**Testing** — чому `supertest`? Чому тести імпортують app напряму? Це нестандартно. Без цього пояснення Claude може запропонувати інший підхід, який зламає все.

**Environment** — простий `.env` нагадування. Гарна практика документувати це явно.

### ❌ Пропустив

**Deployment** — у нас локальна розробка. Якщо потім додаси production, буде окремий документ.

**Database選择理由** — чому in-memory, а не SQLite або MongoDB? Це очевидно з контексту ("starter для курсу"), але можна було додати. Просто не критично на цьому етапі.

**Error handling patterns** — наприклад, як форматувати помилки в JSON-відповідях. Claude це зрозуміє з прикладів коду.

**Дозволи та правила доступу** — CLAUDE.md — це про код, не про дозволи інструментів. Це мав бути `.claude/settings.json`.

---

## Правила дозволів (в settings.json)

Я б мав додати в `settings.json` щось на кшталт:

```json
{
  "permissions": {
    "allow": [
      "bash:npm run dev",
      "bash:npm test", 
      "bash:npm run lint"
    ]
  }
}
```

### Що може піти не так без цього

1. **Тести не запустяться** — Claude попросить дозвіл на `npm test` кожного разу, замість того, щоб просто запустити його
2. **Медленна розробка** — кожна операція зупиняється на дозвіл, навіть якщо це той же `npm run dev` вже п'ятий раз
3. **Claude зупинеться на перевірці коду** — не зможе запустити лінтер без явного дозволу
4. **Невідомі команди** — якщо Claude спробує щось вроде `npm run build` (якщо він не існує), це буде помилка. Білий список захищає від цього.

### Чому я цього не додав (чесно)

1. Я не знав, які інструменти ти використовуватимеш (Node? Python? обидва?)
2. settings.json вже був у .idea/ файлах як IDE конфіг, не було ясно, де його розмістити в проекті
3. Це можна додати пізніше без проблем — це не критично на старті
